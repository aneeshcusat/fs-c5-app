Packaged seed

A diff you review before it touches config

Industry templates seed Application Config lists, flags, and related setup from a packaged industry. Apply is a reviewed diff, not an invisible overwrite.

Admin → Industry templates Route /admin/industry-templates Org flag appconfigEnabled Org Admin

The job of this console

Pick a template, read the diff against current org config, apply only what you intend, then verify lists and flags in Application Config and Feature flags. Never apply blindly on a production org that already has local lists.

Seat at the table

Org administrators. HR admins may be asked to review the diff; they should not treat this as a daily console.

The working rhythm

Open templates, choose an industry, review added and replaced keys, apply, then spot-check Application Config and a test persona menu.

Moments that bring you here

Greenfield tenant. A new line of business that matches a pack. After a sandbox reset. Not for a one-field list edit — that belongs in Application Config.

ⓘ
Templates seed Application Config
The template is not a lasting source of truth. After apply, org.json / Application Config owns the values. Review the diff every time.

Overview

Templates write into Application Config and related source entities. They are not an independent industry database.

How to use

1. Read the diff
Never apply blind on a production org.
2. One pack at a time
Overlapping packs can clobber lists.
3. Checklist first
Finish day-one checklist items that templates assume exist.

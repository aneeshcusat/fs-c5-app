Day-one runway

A phased path to a usable org

The setup checklist is one-time day-one guidance — phases, docs, console links, and an automation playbook — so a new tenant is not configured by folklore.

Admin → Setup checklist Route /admin/setup-checklist Org flag appconfigEnabled HR Admin · Org Admin · implementation partner

The job of this console

Walk phases in order: identity and config, people masters, time rules, approvals, then optional modules. Tick only what the org has actually proven in the live consoles.

Seat at the table

People standing up Tracopus. Day-to-day HR admins return only when a new module is being switched on. Employees never see this page.

The working rhythm

Open a phase, follow the linked console, complete the work there, return and mark it. Use the playbook for jobs and flags last, after masters exist.

Moments that bring you here

First week of a tenant. Adding payroll after HRMS is already live. A new country pack. After an incomplete go-live, to see what was skipped.

ⓘ
Checklist is guidance, not a second config
Ticks do not enable flags or write Application Config. The linked consoles are still the place work happens.

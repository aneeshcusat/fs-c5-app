Leave Policies User Guide

One place for supported leave policies, how to configure them in Global Policy Center, go-live scenarios, and how new CFA requirements map to shipped Tracopus features.

Screen setup checklist: Leave Configuration · Runtime apply/approve: Leave Management · Scenarios: Configure Global Leave

What this guide covers

Tracopus leave has two layers:

  1. Policy configuration — jurisdictions, country templates, versioned team policies, holidays, working days, publish (this guide + Leave Configuration).
  2. Day-to-day runtime — employees apply on People → Leave management; managers approve there or in Workspace → Approvals.
Shipped — India CFA packs Shipped — apply / approve / accrual / CF Partial — AE / SA / US stubs Planned — adoption days TBD
ℹ️
Publishing ≠ balances
Publishing a policy activates eligibility and accrual rules. Opening balances still come from Employee leave config (OB template → dry-run → live) or the accrual schedule — Tracopus does not invent balances.

Domain principles

  • Location-driven policy — entitlements differ by work location / jurisdiction (KA, MH, HR, TN-CBE, …).
  • Two leave years — earned leave uses fiscal Apr–Mar; floating holiday budget uses calendar Jan–Dec.
  • Leave always needs approval — even when attendance auto-approves for some bands.
  • Configurable, not hardcoded — rules live in Global Leave templates / published versions (not hard-coded Sat/Sun).
  • Canonical sources only — Employee, leave types, balance ledger, holidays, TaskActivity promotion; no shadow leave tables.

Quick path (first go-live)

  1. Flags — enable leaveManagementEnabled (+ Global Leave role modules) in Application Config.
  2. Publish policy — Global Policy Center: jurisdiction → apply CFA India template → simulate → publish (or use production prefill SQL for defaults).
  3. Holidays + working days — calendar keys + weekly-off rules.
  4. Balances — Employee leave config OB template / Adjust balance.
  5. Prove — apply spanning holiday → Approvals approve → check timesheet / attendance sync.

Shared across packs: MATERNITY / PATERNITY / MSL / COMPOFF / FLOATING; fiscal Apr–Mar for earned leave; PL CF max 45 with excess LAPSE by default; PH budget 11 calendar-year floating remainder.

Shared special / holiday rules

  • Maternity — 182 days (1st/2nd child), 84 days (3rd+); start ≤8 weeks before expected delivery; FE maps child # to days.
  • Paternity — exactly 5 consecutive days inside apply window.
  • Comp-off — weekend/statutory ≥6h or weekday >15h; 90-day use-or-expire from work day.
  • Floating — pick from published catalogue; reject if catalogue / budget missing.
  • MSL — tenure months 60 / 120 / 180 / 240; catch-up window supported.

How to configure leave policies

Primary console: Admin → Leave admin → Global Policy Center (/admin/leave/global-policy-center). Requires leaveAdditional.globalLeavePoliciesEnabled and adminModules.globalLeavePoliciesEnabled.

  1. Enable flags

    Application Config → org leaveAdditional.leaveManagementEnabled (+ Global Leave / leavePolicies role modules). Minimal flag flips only — do not invent full App Config for NULL-config teams.

  2. Create or select a jurisdiction

    e.g. IN, IN-KA, IN-MH. Used for resolve, holiday calendars, and working-day scope.

  3. Apply a country / CFA template into a draft

    Choose CFA-IN-KA (etc.) or blank draft. Edit type entitlements, accrual, carry-forward, special leave JSON as needed.

  4. Simulate / Policy Test Lab

    Dry-run a sample employee. Lab may gate publish. Guide: Policy Test Lab.

  5. Assign holiday calendar key

    Key must match People → Holidays locations (e.g. IN-KA). Optionally publish Legal Calendars first.

  6. Working-day rules

    /admin/leave/working-day-rules — team default, jurisdiction pattern, or employee override. “Country” means leave jurisdiction assignment.

  7. Publish version

    Activates accrual / eligibility. Published versions are immutable — clone a new draft to change.

  8. Opening balances

    Employee leave config: Download OB template → fill from ZingHR → dry-run import → live; or Adjust balance per employee.

  9. Prove apply → approve

    People → Leaves apply; Workspace → Approvals or pending panel approve; confirm day count, balance debit, timesheet promotion.

  3. Smoke apply → approve on a flagged team.

Example: Bengaluru employee fiscal PL

  1. Employee jurisdiction resolves to CFA-IN-KA (PL 18 / SL 12 + WWL).
  2. Opening PL balance imported or accrued after April front-load / monthly job.
  3. Employee applies 3 working days spanning a People holiday — numberOfDays = 2.
  4. Manager approves → balance debited → leave TaskActivities promoted → optional attendance LEAVE marks.

Example: Floating holiday pick

  1. HR published floating catalogue for the calendar year.
  2. Employee selects FLOATING + catalogue option in apply drawer.
  3. Without published catalogue / budget, apply is rejected with a clear message.
  4. January renew job credits FLOATING entitlement (idempotent).

Common mistakes

  • Expecting balances after publish alone — import or wait for accrual.
  • Inventing OB CSV amounts without ZingHR / HR export.
  • Holiday calendar key mismatch → days still counted.
  • Using PL for paternity (ZingHR historical remap) — paternity is PATERNITY.
  • Skipping dry-run on bulk import.
  • Global Leave flag off while editing classic policies only — resolve path differs.

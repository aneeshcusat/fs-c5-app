Leave approval scenarios

Coverage map for the native leave lifecycle behind leaveManagementEnabled: create → submit → approve / reject / withdraw / cancel, plus overlap, half-day, delegation, on-behalf, and ZingHR SYNCED coexistence. Side effects include balance ledger, Approvals inbox, attendance sync, and TaskActivity LEAVE promotion.

Happy path (status → side effects)

1

Create draft

CREATED. Holiday-aware day count; optional half-day on single calendar day. No pending hold.

2

Submit

SUBMITTED; reserve pending balance; notify manager / delegates. Appears on Leave pending + Approvals inbox.

3a

Approve

APPROVED; debit (releases hold); promote TaskActivity LEAVE; attendance LEAVE / HALF_DAY when sync on.

3b

Reject

REJECTED; release hold; no TaskActivity / attendance write. Comment required.

4

Withdraw (owner)

CREATED or SUBMITTED → WITHDRAWN; release hold if submitted. Blocked on APPROVED / SYNCED.

5

Cancel (owner)

SUBMITTED / APPROVED / SYNCED → CANCELLED; release hold or creditOnCancelAfterApprove; demote TaskActivity; reverse attendance.

Side-effect checklist

Effect Approve Reject / Withdraw (pre-approve) Cancel (post-approve / SYNCED)
Status APPROVED REJECTED / WITHDRAWN CANCELLED
Balance Debit Release hold / no debit Credit back
Pending + Approvals inbox Cleared Cleared N/A
Attendance (sync on) LEAVE / HALF_DAY Unchanged Reversed
TaskActivity Upsert LEAVE None Demoted (deleted)
Audit Actor + authority Actor CANCEL
Siblings Untouched Untouched Untouched

On approve — promote

LeavePromotionService.promote upserts TaskActivity TaskType.LEAVE, then LeaveAttendanceSyncService.syncAfterPromotion.

On cancel — demote via promote

Cancel sets CANCELLED then calls promote; cancelled path soft-deletes existing LEAVE activities and syncs attendance reverse.

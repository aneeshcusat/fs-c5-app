The job of this console

Assign personas to a role, set the default, preview menus, then open Advanced only when a single flag must differ. Do not grant Site Admin to fix one missing page — use persona navigation or a tighter permission.

Seat at the table

Administrators. Employees never edit roles. Managers do not self-elevate.

The working rhythm

Pick a role, set personas and default, preview, save, then Advanced if needed. Prove with a test user. Coordinate with persona navigation and flags.

Moments that bring you here

A new HRBP role. Someone stuck without timesheet. After a module launch. When the switcher shows personas they should not assume.

ⓘ
Role.json is the matrix; personas are the lens
Application Config and flags still gate modules. This console does not replace ApprovalAuthority or Employee records.

Roles attach to org units via ApplicationConfigRoleBar — users inherit through team membership, not direct user assignment. After changes, affected users should re-login to refresh encrypted access.

Evaluation order at runtime

  1. Role module / menu flags (*Enabled in hrmsModules, projectModules, …)
  2. Role personaModules — or Automatic heuristic when never saved
  3. Org pagePersonaMap when an override exists for that route
  4. Org disabledPersonas, disabledPaths, disabledModules — always win

Menu visibility is not the same as API CRUD permission — backend RBAC enforces actions independently.

How to use

1. Confirm gates
Org rbacAdminEnabled and your admin role adminModules.rolesEnabled.
2. Pick a role template
Start from Site Admin or clone Manager / Employee templates.
3. Persona access
Set allowed personas, default, and switcher — or leave Automatic until you Save explicit personas.
4. Advanced (optional)
Tune module visibility and CRUD groups; disable dangerous flags on custom roles.
5. Assign via Role Bar
Map the role to delivery / HR org units in Application Config.
6. Verify
Sign in as a test user — confirm switcher, sidebar, and deep links.

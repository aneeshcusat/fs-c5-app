Leave Localization

Register view for locale packs and policy translations — no self-serve write UI; seed via API.

Register view — seed via API. Flowcharts: locale pack → jurisdiction → UI strings.

Locale packs

Translations of policy, not a new policy

Leave localization is locale packs and policy translations. No self-serve write UI; seed via API. The policy math stays in Global Policy Center; this is language.

Admin → Leave localization Route /admin/leave/localization HR Admin · Org Admin

The job of this console

See which packs are present, seed missing translations, and confirm employees see policy names in their locale. Do not fork policy logic per language.

Seat at the table

HR administrators and implementation partners. Employees only see the translated strings at apply time.

The working rhythm

Open the register, identify a missing locale, seed via API, prove on a test user with that locale.

Moments that bring you here

A new country. A policy renamed in English only. After a pack import. When a string still shows a key.

ⓘ
Strings, not balances
Localization never changes day counts. Policy Center still owns the rule.

Overview

Leave localization keeps region-specific wording aligned with legal calendars and policy packs. This screen is a register only — no self-serve write UI; seed via API.

How to use

1. Open Localization
Admin → Leave → Localization.
2. Review locale packs
Inspect packs and translations; seed or update via API.
3. Check jurisdictions
Confirm packs align with countries used in Policy Center.
4. Spot-check Leaves
When packs are live, verify copy as a test employee.

Admin & Access

How permissions shape what you see in the Luxury UI — module menus, project scoping, timesheet date policies, and application configuration.

Access overview

Tracopus uses role-based access control enforced on both client and server. The UI hides menus and actions you cannot use rather than showing disabled controls. Access is evaluated at multiple levels:

  1. Module level — can you see HRMS, Sales, or Project directories at all?
  2. Page level — which routes within a module appear in the sidebar?
  3. Action level — create, edit, delete, assign, mark attendance, etc.
  4. Record level — project membership, team scope, shared vs private visibility
  5. Field level — timesheet date windows, report type availability

Mobile receives an encrypted access control payload on login; web evaluates permissions from the authenticated user session.

Module access

The left sidebar shows HRMS, Sales, and Project directories only when menuAccessControl flags them active for your user:

Access-controlled routes

These pages require additional permission flags beyond module access:

  • File manager (/project/filemanager)
  • Chat (/project/chat)
  • Calendar (/project/calendar)
  • Search (/project/search)
  • Settings (/hrms/settings)
  • Application config (/hrms/appconfig)

Icon rail entries for these features hide when access is denied.

Project access

Team scope

Team selection filters on list pages limit data to projects and records associated with selected teams. Your default team appears in the sidebar company chip.

Project membership

Project details enforce membership and team rules:

  • Non-members may see read-only or denied views depending on shared visibility settings
  • Cross-team access without membership renders read-only project details
  • Members tab manages invitations, roles, and access chips

Shared vs private projects

Project list "Shared visibility" donut reflects how many projects are shared across teams vs restricted. Private projects appear only to members and elevated roles.

Create permissions

Create buttons on lists (projects, bids, POs, employees) and planner assign actions require explicit create permissions. Executive planner view is read-only when create is disabled.

Timesheet access rules

Timesheet permissions (timeSheet branch of access control) govern web and mobile equally.

RuleEffect
enableTimeSheetEntry falseNo days allow entry — entire week disabled
Project work item windowsBillable entry only within min/max create dates derived from working-day offsets
Non-project work item windowsSeparate date range for non-billable entries
Leave/holiday rulesallowLeaveAndHolidayForFuture / ForPast control leave booking direction
Hour thresholdsRules like disable create before Y working days after X hours logged

On mobile, disabled days show grey titles in the week list and blocked add buttons on the Record screen with snackbar message: "Time entry is not allowed for this date."

Managers with multi-employee timesheet permission can switch employees on the web Timesheet page header.

Application configuration

/hrms/appconfig — hierarchical configuration tree per team (admin access required).

What admins configure

  • Application configuration (org.json) — dropdown lists, service line trees, notification emails, feature toggles
  • Access control (role.json) — module visibility, CRUD permissions, timesheet windows, report access
  • Team-scoped overrides inherited from parent org nodes with lock/hide/inherit controls
  • Role bar for assigning role templates to org units during editing

Open full Application Configuration reference → — every key from org.json and role.json with descriptions, sample values, and UI workflow notes.

Org-wide notification defaults.

Personal UI preferences (palette, font) live in the Settings right sidebar and localStorage — not org-wide.

Reports & feedback permissions

Report types in the REPORT dropdown are filtered by permission — users only see reports they can run. Feedback template configuration and campaign launch similarly require elevated project permissions.

External feedback and invoice document routes (/document/…) use tokenized links that bypass full app auth for respondents while keeping responses scoped.
